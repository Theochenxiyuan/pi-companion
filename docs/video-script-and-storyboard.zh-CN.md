## 1. 这支视频只讲什么

这不是一支功能总览，也不是智能体对话演示。视频只传达一个观点：

> 在工作发生的地方启动智能体，让它在后台工作，只在需要你时出现。

Pi Companion 是我给自己做的 Pi 桌面 GUI；为了验证这套交互方式，我在里面加入了快捷任务入口和任务监视器。

观众看完后应当能复述三件事：

1. 不必先打开聊天应用，任务可以直接从当前目录或文件开始。
2. 不必一直盯着智能体对话，任务监视器会常驻桌面并在需要人时出现。
3. 智能体对话仍然存在，但它是深入检查完整过程的界面，不是所有任务的默认入口。

## 2. 标题、封面与发布摘要

### 推荐标题

**智能体不该住在聊天窗口里：我做了一个快捷任务入口和任务监视器**

备选标题：

- 我给自己的智能体做了两个新界面
- 如果智能体可以在后台工作，只在需要你时出现
- 我给 Pi 做了一个快捷任务入口和任务监视器

### 封面

画面左侧是资源管理器中的 `询问 Pi Companion`，中间是收起状态的任务监视器，右侧是权限请求状态的任务监视器。不要把完整的智能体对话主窗口放在封面中心。

封面主文案：

> 别再盯着智能体对话

角标小字：

> 快捷任务入口 · 任务监视器 · 开源

### 一句话发布摘要

> Pi Companion 是我给自己做的 Pi 桌面 GUI。为了验证任务能否直接从当前目录和文件开始，以及智能体能否在后台运行、只在需要时让我介入，我在里面加入了快捷任务入口和任务监视器。项目已经开源，目前可从源码构建运行。

## 3. 演示任务准备

不要直接拿 Pi Companion 自己的复杂仓库做录屏。准备一个体积小、文件名清楚、测试可在十几秒内结束的演示仓库，确保观众不用理解业务也能看懂任务。

推荐场景：选中一个实现文件和对应测试文件，让智能体修复一个确定的小问题、补测试并运行相关测试。

演示任务描述示例：

> 检查这两个文件，修复 CSV 导出日期偶尔提前一天的问题，补充回归测试，并运行相关测试。不要改动无关代码。

录制前准备：

- 让该任务可以稳定在 45–75 秒内完成。
- 权限模式应能在运行测试时产生一次真实的授权请求。
- 预先确认最终摘要能显示“修改了哪些文件”和“测试是否通过”。
- 使用无隐私信息的临时 Windows 用户名、目录名和仓库内容。
- 关闭桌面通知、聊天软件、输入法悬浮提示和会暴露账号信息的托盘图标。
- 资源管理器、编辑器与桌面背景保持简洁；桌面只保留任务监视器。
- 录制真实交互，但剪掉不可控的等待时间。不要伪造不存在的能力。

## 4. 完整旁白稿

> Pi Companion 是我给自己做的一个 Pi 桌面 GUI。我在里面加入了快捷任务入口和任务监视器，因为我想验证两件事。
>
> 第一，智能体任务能不能从工作发生的位置开始，而不是先打开一个聊天窗口。第二，当任务需要运行几分钟时，我能不能继续做别的事，只在它需要我时介入。
>
> 这是我现在的实现。我要处理这两个文件，所以直接在资源管理器里选中它们，点击“询问 Pi Companion”。快捷任务入口出现在鼠标附近，目录和附件已经带进来了。我只需要描述任务，然后点击“开始任务”。
>
> 提交后，快捷任务入口就消失了。我可以继续做别的事。智能体的状态留在桌面的任务监视器里：它正在读什么、运行什么，以及现在是否需要我。
>
> 普通进度不会抢走焦点。只有遇到权限请求或问题时，任务监视器才会把需要处理的内容放到最前面。我可以允许这一次操作，也可以直接调整智能体的方向，不必重新找到那一个聊天窗口。
>
> 任务结束后，任务监视器给出精简结果、文件变更和测试状态。只有当我想检查完整过程、查看具体修改，或者继续对话时，才进入智能体对话。
>
> 这就是我想探索的桌面智能体层级：快捷任务入口负责开始，任务监视器负责陪伴和介入，智能体对话负责深入检查。
>
> 这套交互不是关于智能体界面的最终答案，但它已经成为这个自用 GUI 里可以实际工作的功能。Pi Companion 已经开源，目前还处在早期阶段，需要从源码构建。如果你也对这种工作方式感兴趣，可以在 GitHub 查看代码和设计。

## 6. 屏幕字幕清单

字幕只用于帮助观众建立结构，不重复每句旁白。全片最多使用以下六组：

1. `我在自己的 Pi GUI 里加了两个功能`
2. `从当前上下文启动`
3. `在后台运行`
4. `只在需要你时介入`
5. `启动 → 监视 → 深入查看`
6. `开源 · 早期阶段 · 从源码构建`

所有面向观众的旁白、字幕和图中文字统一使用产品中文界面的正式名称：`快捷任务入口`、`任务监视器`、`智能体对话`。资源管理器入口按真实界面写作 `询问 Pi Companion`。

## 7. 画面与声音原则

### 画面

- 以真实桌面录屏为主，不用抽象科技动画替代交互。
- 鼠标点击前停 0.2–0.4 秒，保证观众能跟上动作。
- 放大关键区域时使用平滑裁切，不使用夸张的镜头震动或发光描边。
- 除等待过程外，尽量使用连续镜头，证明快捷任务入口与任务监视器确实处于桌面工作流中。
- 所有状态、文件数量和测试结果都必须与真实录制一致。

### 声音

- 旁白保持克制，像解释一个产品判断，而不是广告喊话。
- 背景音乐选择稳定、轻微推进但没有强鼓点的曲目。
- 保留少量鼠标点击、窗口出现和任务完成提示音，音量低于旁白。
- 不需要为每次状态变化添加音效；任务监视器的价值正是“不打扰”。

## 8. 录制素材清单

完成录制前逐项确认：

- [ ] 资源管理器选择两个文件并打开右键菜单。
- [ ] `询问 Pi Companion` 入口近景。
- [ ] 快捷任务入口在鼠标附近出现。
- [ ] 工作目录与附件已经带入。
- [ ] 输入任务并开始工作的完整操作。
- [ ] 任务监视器收起状态下的排队、运行、等待与完成状态。
- [ ] 任务监视器展开状态下的精简活动流。
- [ ] 一次真实权限请求或智能体提问。
- [ ] 一次直接介入操作。
- [ ] 完成摘要、文件变更和测试状态。
- [ ] 从任务监视器打开智能体对话。
- [ ] 智能体对话中的完整过程、差异/文件变更和继续对话入口。
- [ ] GitHub 仓库首页与许可证信息。

## 9. 可裁切的短版本

完整版发布后可从同一素材裁出 45 秒版本，不另讲新故事：

- 00–05 秒：资源管理器右键启动 + 开场问句。
- 05–15 秒：快捷任务入口自动带入目录与附件并提交。
- 15–27 秒：任务监视器显示后台运行状态，不抢焦点。
- 27–36 秒：权限请求与完成结果。
- 36–41 秒：快捷任务入口 → 任务监视器 → 智能体对话。
- 41–45 秒：开源仓库与“从源码构建”。

短版本旁白：

> Pi Companion 是我给自己做的 Pi 桌面 GUI。为了验证一种新的智能体工作方式，我在里面加入了快捷任务入口和任务监视器：直接从当前目录和文件启动任务，然后继续做自己的事；只有需要权限、回答或调整方向时才介入。需要检查完整过程时，我再打开智能体对话。Pi Companion 已经开源。
