# 阶段 5：完整 Agent Chat

## 交付结论

阶段 5 已完成。Agent Chat 不再只是当前 Run 的监视界面，而是 Task 的主要工作区：用户可以新建任务、恢复完整多 Run 会话、管理历史与回收站、检索任务、继续已完成任务，并在 Chat 输入区直接管理附件。Monitor 与 Chat 继续共享同一 `TaskProjection`，没有建立第二套运行状态。

本阶段同时完成了增量 Bridge、Transcript 虚拟化、5000 事件性能验收、Markdown/代码/链接安全收口和前端验收门禁。下一阶段可以直接围绕文件 Diff、测试证据与恢复展开。

## 用户可见成果

### Task 工作区与完整会话

- Chat、完整任务历史和回收站直接切换主区，三者互斥；左侧“最近”始终保留快速入口。
- 历史支持名称、目录和摘要搜索，以及进行中、已完成、已停止和失败状态筛选。
- 任务支持重命名、移入回收站、恢复、永久删除和清空回收站。
- 从完整历史打开不在“最近”可见范围内的任务时，会把它临时显示在“最近”第一项；该投影不改变持久化排序，改选原有最近任务后列表恢复。
- 最近任务被移入回收站后，SQLite 查询会继续加载后续任务补足默认数量。
- 同一 Task 可顺序包含多个 Run；打开历史任务会按时间恢复全部 Run，继续发送会追加新 Run，不覆盖旧会话。

### Transcript 与运行交互

- User、Assistant、Thinking、Tool、Interaction、Notice 和最终状态按语义块渲染。
- 连续工具调用可分组折叠；摘要、标准和详细模式控制信息密度。
- 授权和提问可在 Chat 内完成，Steer 与 Follow-up 队列随投影更新。
- Monitor 的“打开 Agent Chat”进入当前 Task；两个窗口显示同一状态、队列和交互请求。
- 面向用户的重启/中断提示已收口，不显示内部 Pi Session 恢复术语。

### Chat 附件

- 输入区新增可扩展的 `+` 操作菜单，“添加附件”是当前第一个菜单动作。
- 使用 Windows 原生多文件选择器；附件按不区分大小写的完整路径去重，并可在发送前移除。
- Explorer → Composer 带入的文件和文件夹附件可继续在 Chat 中使用。
- 所有入口统一为最多 64 个附件；创建 Run 前重新规范化路径并检查文件或文件夹是否仍存在。
- 任务运行期间禁用附件操作，避免附件被误解为会随 Steer/Follow-up 消息发送。

## 技术实现

### Snapshot、Sequence 与增量 Bridge

- Bridge 协议版本为 9。
- 首次连接、WebView 重载、任务切换和 Sequence 缺口使用完整 Snapshot 收敛状态。
- 正常运行只发送追加事件与 `TaskDelta`；Transcript 和 Activity 通过稳定 ID 原位更新。
- 前端检测 Task、Run 或 Sequence 不连续时主动请求新 Snapshot，不猜测或跳过缺失事件。
- 前端只保留最近 100 条原始调试事件，完整用户会话由语义 Transcript 承载。

### 虚拟列表与 5000 事件

- Transcript 使用窗口化虚拟列表，按估算高度和 overscan 只挂载可见附近节点。
- 工具组的子列表同样虚拟化，避免详细模式一次挂载全部工具节点。
- 5000 条顺序增量事件投影测试验证不需要反复发送完整 Task Snapshot。
- 5000 行虚拟列表验收验证 DOM 节点保持在小窗口内，输入区不随会话规模重建。

### Markdown、代码和链接安全

- Markdown 禁止原始 HTML 直通，渲染结果再次经过 DOM 清理。
- 代码围栏按文本输出，示例中的 `<script>` 不会成为 DOM 节点。
- 链接仅允许显式 `http`、`https` 和 `mailto`，统一增加 `noopener noreferrer`。
- `javascript:`、`data:`、`file:`、相对路径和远程图片不进入可执行或可加载 DOM。
- 外部链接由桌面 Bridge 交给系统打开，WebView 页面不直接导航。

### Task 管理与持久化

- SQLite 保存 Task、Run、附件、事件、交互证据和 Pi Session 元数据。
- SQLite 以任务最近一次实际活动时间排序；创建/继续 Run、Run 事件、重命名和恢复会更新时间，单纯打开任务不会更新时间。相同时间使用任务 ID 稳定排序；当前 Chat 在已加载集合上即时执行搜索与状态筛选。
- 升级迁移会用 Run 创建时间和真实 Run 事件时间重建一次现有非删除任务的活动时间，清除旧版本“打开任务即更新时间”留下的排序数据；迁移完成后的重命名等新活动不会被后续启动覆盖。
- 新 Run 会同步当前 Task 附件集合；附件新增和移除可以在重启后恢复。
- 应用重启时遗留活动 Run 只转换一次为 `Interrupted`，完整历史仍可打开并继续。

## 人工验收建议

1. 从完整历史打开一个不在最近列表中的任务，确认它恢复所有 Run 并临时显示在最近第一项；改选原有最近任务后列表恢复原顺序。
2. 在最近列表移入回收站，确认列表自动补位；随后恢复、永久删除并清空回收站。
3. 在 Chat 通过 `+` 添加多个文件，重复选择同一文件，确认只显示一项；删除文件后发送，确认明确提示附件不可用。
4. 运行任务期间确认附件入口禁用，Steer 与 Follow-up 仍按各自队列发送。
5. 重载 WebView，确认当前 Task、完整 Transcript、交互卡片和 Sequence 继续一致。
6. 打开 5000 事件预览，滚动、切换详情级别并输入文本，确认没有明显卡顿或横向溢出。
7. 输入包含原始 HTML、脚本 URL、代码围栏和远程图片的 Markdown，确认只显示安全文本和允许链接。

## 已知边界

- 调度器仍保持单活动 Run；多任务同时运行不是阶段 5 的交付范围。
- Chat 的“添加附件”当前选择文件；文件夹附件仍可通过 Explorer → Composer 带入，后续可作为 `+` 菜单的新动作扩展。
- 真实供应商凭据下的长时间压力测试仍需在发布候选版本执行。
- 开发包仍是未签名稀疏包；正式安装、更新和卸载体验属于阶段 7。
- 文件变化证据、Git/非 Git Diff、测试退出码聚合和单文件恢复尚未实现，属于阶段 6。
